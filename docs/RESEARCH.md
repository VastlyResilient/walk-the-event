### 1.1 Bobby's station-splat workflow (TOP PRIORITY)
- Source: https://x.com/bilawalsidhu/status/2061134940813611505
- What it actually says: "A few hundred photos of my parent's old home… 3D gaussian splat made w/ **RealityCapture + LichtFeld**." Bilawal points to his YouTube ("Mapping the World with Bilawal Sidhu") for the gaussian-splatting deep dive. MrNeRF (Janusch Patas) confirms spelling: **LichtFeld**.
- Conclusion: The referenced pipeline is **many photos → RealityCapture (camera alignment) → LichtFeld training → splat**. For station pods with only a handful of photos per station, RealityCapture may under-constrain; LichtFeld can take COLMAP-format poses, so our existing COLMAP/pycolmap solve can substitute for RealityCapture at no cost.
- Do: Per station, run pycolmap on that station's photo set (+ extracted close video frames), train with LichtFeld if a GPU is available; else use Marble multi-image (paid export) or Apple SHARP for single-photo stations. Clean in SuperSplat, export `.spz`/`.sog`, render with Spark. 2.5D depth-parallax photo is the documented fallback per pod.

### 1.3 SuperSplat Walk Mode (splat UX benchmark)
- Sources: https://x.com/willeastcott/status/2036771869206995049 · https://blog.playcanvas.com/new-in-supersplat-walk-mode-streamed-lod-and-easy-upload/
- Findings: Walk Mode = first-person splat navigation; default **click-to-walk** (tap a point, camera glides there), WASD on desktop, pinch-to-move on mobile. Powered by a **voxel-based collision system** generated by SplatTransform (collision generation in developer preview). Same release added **streamed LOD built on SOG** format — scenes >10M Gaussians stream to any device; desktop handles ~4M Gaussians comfortably.
- Do: Steal the interaction model for station pods: default gentle auto-orbit + tap-to-move. Budget each pod ≤ ~1–2M Gaussians for mobile; use SOG streamed LOD if pods grow.

### 1.6 Apple SHARP (single photo → splat)
- Sources: https://x.com/svrc/status/2001591705254904089 · https://x.com/revelium_studio/status/2009570090568577045 · https://github.com/apple-aiml-research/ml-sharp · https://apple-aiml-research.github.io/ml-sharp/
- Findings: SHARP regresses a metric 3D Gaussian scene from ONE photo in a single feedforward pass (<1 s on GPU; ~30 s on an M4 MacBook Air). MIT code, model checkpoint auto-downloads (`sharp predict -i imgs -o gaussians`). Output: standard 3DGS `.ply` (OpenCV convention, x-right/y-down/z-forward — must re-center/rotate for third-party renderers). CPU/CUDA/MPS inference; `--render` video needs CUDA. Beats prior SOTA by 25–34% LPIPS. Revelium hosts a free web app (lab.revelium.studio/ml-sharp) usable as a no-install fallback.
- Do: SHARP is the default for **single-photo stations** and for quick hero-viewpoint pods. Convert `.ply` → `.spz` (SuperSplat CLI or spz tools), verify hero-view fidelity before shipping; fall back to 2.5D parallax if the ±25° orbit breaks.

## 2. Scroll-scrub video (core Bucket-1 mechanic)

- Sources: https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API/Video_processing_concepts · https://github.com/w3c/webcodecs/issues/87 (seek-to-frame-number) · https://github.com/w3c/webcodecs/issues/557 (webcodecs seek slower than video element) · scroll-widget write-ups (scrollytelling.ai, github.com/SunnyMarthak/scrollreel)
- Findings: The Apple-product-page pattern is: pre-encoded video, scroll position → target timestamp, render frames via canvas. Two viable engines: (a) `<video>` + `requestVideoFrameCallback` + `currentTime` nudging — universally supported but seek latency depends on keyframe density (needs short GOP, keyint 6–12, ALL-INTRA ideally); (b) WebCodecs `VideoDecoder` with a decoded-frame ring buffer — frame-exact and fastest for fine scrubbing, but per W3C issue #557 seek (decoder reset) is slower than video-element seek unless you decode sequentially through GOPs; no WebCodecs in older Safari.
- Conclusion: Hybrid — H.264 short-GOP (keyint 8) chaptered MP4s + video-element scrubbing as the baseline (works on iOS Safari), WebCodecs sequential-decode ring buffer as the progressive enhancement on desktop Chrome/Android. Benchmark both on an iPhone-class device before committing; log result in DECISIONS.md.
- Do: Encode 720×1280 primary tier + 1080×1920 desktop tier, chapter-split for ≤3 s first interactive; preload next chapter during idle.

## 3. Photogrammetry / splats (toolchain summary)

- Spark (three.js splat renderer): https://github.com/sparkjsdev/spark — World Labs-built, MIT; loads PLY/compressed-PLY/SPZ/SPLAT/KSPLAT/SOG; multiple sorted splat objects; per-splat animation, shader graph; targets 98%+ WebGL2. **This is our pod renderer.** `npm i @sparkjsdev/spark`.
- SuperSplat (editor/cleanup): https://playcanvas.com/products/supersplat — free web editor; SplatTransform CLI for conversion + voxel collision generation.
- LichtFeld: high-quality open 3DGS trainer (per Bilawal workflow; needs GPU + COLMAP-format poses).
- Marble: paid no-GPU world generation (see 1.4).
- SHARP: single-photo splats, local, free (see 1.6).
- Gracia: 4DGS streaming platform — parked (see 1.9).
- Pipeline decision tree per station: ≥8 good photos → COLMAP → LichtFeld (GPU) else Marble multi-image → SuperSplat cleanup → SPZ/SOG → Spark. 1–3 photos → SHARP → same tail. 0 usable → 2.5D depth-parallax card (log it).

## 4. Camera solve, depth, masks

- COLMAP: https://colmap.github.io/tutorial.html — standard SfM; use pycolmap at 6–10 fps, spline-interpolate to 30 fps. GLOMAP (https://github.com/colmap/glomap) is the faster global alternative if COLMAP registration fragments on the upstairs footage.
- Video Depth Anything (CVPR 2025 highlight): https://github.com/DepthAnything/Video-Depth-Anything — temporally consistent depth for arbitrarily long videos; Small model 9.1 ms FP32 / 7.5 ms FP16 per 32-frame chunk on A100; supports streaming mode + grayscale video output (exactly what the runtime needs for the depth-parallax look-around). Metric-depth variants exist if world-scale placement needs it.
- SAM 2 video propagation: https://github.com/facebookresearch/sam2 (video predictor notebook: colab link in repo) — zero-shot mask propagation for station region tracking + people occlusion masks for the guide.
- Gyroflow stabilization — **IMPORTANT NEGATIVE FINDING**: https://docs.gyroflow.xyz/app/getting-started/supported-cameras/mobile-phones — Gyroflow needs gyro data recorded at capture time by a logger app (Sensor Logger, MotionCam Pro, etc.). Stock iPhone camera footage (our inputs) has no usable Gyroflow motion track, and OIS/in-camera stabilization interferes anyway. **Conclusion: skip Gyroflow; use ffmpeg vidstab two-pass with light crop, as the prompt's fallback.**

Webhooks available with signature verification. Unsupported-value requests fail fast — good for model screening.

Budget math: ~5 s × $0.50 ≈ $2.50/clip at 720p; 8 stations × 3 candidates ≈ $60 — exactly the VIDEO_BUDGET_USD cap, so screen models on one station first. Free fallback stays the 2.5D depth dolly-push.
